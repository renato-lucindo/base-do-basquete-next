# Plano de implementação — fundação

> Execução: agente principal nesta conversa, com a skill executing-plans; autonomia já autorizada pelo responsável.

**Objetivo:** acesso administrativo real por senha no Worker, com projeto Supabase independente, migrations próprias, RLS e tipos verificados.

**Arquitetura:** monólito modular TypeScript do pacote. Browser chama somente o Worker da aplicação; Auth e Data API são integrações de servidor, com identidade do usuário e autorização explícita. O protótipo fictício permanece disponível enquanto a fundação é validada.

**Stack:** React/Vite/TypeScript existentes; Web APIs no servidor; Cloudflare Workers e Supabase Postgres/Auth/Storage privado. Fixar versões e consultar documentação atual antes de adicionar ferramentas.

**Especificação:** `especificacao/BASE-DO-BASQUETE-ARQUITETURA-20261022/docs/ARQUITETURA.md`, `VALIDACAO.md` (etapa 2, A27/A29/A30) e orientações posteriores em `docs/AJUSTES-DE-EXPERIENCIA.md`.
